# MMSSTV DSP Implementation

This document describes the signal-processing implementation in the original
MMSSTV source. The overall application structure is covered in
[architecture.md](architecture.md), and protocol formats are covered in
[sstv/modes.md](../sstv/modes.md).

## Source Map

The main DSP implementation is distributed across:

| Source | Responsibility |
| --- | --- |
| `fir.h`, `fir.cpp` | FIR/IIR design, convolution, resonators, LMS, notch |
| `sstv.h`, `sstv.cpp` | VCO, discriminators, level tracking, detection, AFC |
| `Fft.h`, `Fft.cpp` | Spectrum collection and FFT |
| `Sound.h`, `Sound.cpp` | Real-time processing order and DSP ownership |
| `Wave.h`, `Wave.cpp` | WinMM/MMW audio buffering |
| `Main.cpp` | Raster decoding, TX protocol generation, DSP UI updates |
| `ComLib.h`, `ComLib.cpp` | Sampling globals and shared configuration |

The DSP classes are not a standalone library. They include VCL headers, read
global configuration, use Windows facilities, and expose state directly to the
main form.

## Signal Paths

### Receive

```text
PCM input
  -> double sample block
  -> optional FIR notch
  -> optional LMS line enhancer or adaptive notch
  -> two-sample averaging
  -> selectable receive FIR BPF
  -> level tracking and detector AGC
  -> parallel tone resonators
  -> VIS, sync, FSK, and AFC state machines
  -> PLL, zero-crossing, or Hilbert FM discriminator
  -> demodulated-frequency and sync-envelope page ring
  -> UI-thread raster decoder
```

The sound worker reads blocks, but `CSSTVDEM::Do()` processes each sample
individually (`Sound.cpp:341-365`). FFT collection branches from the processed
input block after demodulation.

### Transmit

```text
UI-thread image/protocol encoder
  -> frequency-per-sample ring
  -> optional command smoothing
  -> table-driven sine VCO
  -> channel-dependent gain
  -> FIR output filter
  -> PCM output FIFO
```

`CSSTVMOD` only converts frequency commands to PCM. Image sampling, VIS, line
timing, and identifiers are generated by `Main.cpp`.

## Sampling Model

The central sampling globals are declared in `ComLib.h:84`:

| Value | Meaning |
| --- | --- |
| `SampBase` | Nominal PCM rate used to open the sound device |
| `SampFreq` | Calibrated logical rate used by SSTV timing and DSP |
| `SampSize` | Audio worker block size |
| `FFTSamp` | Effective FFT rate after display decimation |
| `FFTSampType` | No decimation, every second sample, or every fourth |

`InitSampType()` in `ComLib.cpp:106` selects a nominal rate, scales the block
size relative to 2048 samples at 11025 Hz, and configures FFT decimation. The
supported nominal rates are 6000, 8000, 11025, 12000, 16000, 18000, 22050,
24000, 44100, and 48000 Hz.

The device is opened at `SampBase`, while filters and SSTV timing normally use
`SampFreq`. This permits sound-card clock calibration and slant correction
without requesting a nonstandard hardware PCM format. TX has an additional
sample-rate offset setting.

Audio is represented as `double` with 16-bit PCM magnitude. Ordinary
demodulated values use approximately this convention:

```text
1500 Hz -> +16384
1900 Hz ->      0
2300 Hz -> -16384
```

`CSSTVDEM` negates the discriminator result before publishing it to the raster
decoder (`sstv.cpp:2288`). Time is represented by sample counters; floating
accumulators are used where repeated integer rounding would drift.

## FIR Processing

### Filter Design

`MakeFilter()` in `fir.cpp:302` constructs low-pass prototypes from a
Kaiser-windowed sinc. The Kaiser beta follows the usual attenuation-dependent
empirical formula. The prototype is normalized for unity DC gain and transformed
to high-pass, band-pass, or band-elimination form.

The `tap` argument is the filter order, so the implementation emits `tap + 1`
coefficients. This convention is significant when reproducing group delay.

`MakeHilbert()` in `fir.cpp:429` creates a band-limited Hilbert transformer and
applies a Hamming window.

### Convolution

`DoFIR()` shifts a delay line and calculates a dot product. `CFIR2` instead
stores two copies of a circular sample history, allowing the convolution to
walk through contiguous memory without modular arithmetic (`fir.cpp:1062`).

`CFIR2` supports internally or externally owned coefficients and can return the
center-delayed real sample together with a Hilbert-filtered quadrature sample.

### Receive and Transmit Filters

`CSSTVDEM::CalcBPF()` in `sstv.cpp:1522` generates ordinary, sync-search, and
narrow-mode receive filters. At 11025 Hz the ordinary presets are approximately:

| Preset | Order | Passband | Design attenuation |
| --- | ---: | --- | ---: |
| Wide | 24 | 1100/1200-2600 Hz | 20 dB |
| Narrow | 64 | 1100/1200-2500 Hz | 40 dB |
| Very narrow | 96 | 1100/1200-2400 Hz | 50 dB |

The sync-search filter extends lower, while narrow SSTV uses mode-specific
bands around 1600-2500 Hz. Changing a delay-producing filter adjusts `m_Skip`
to compensate for the group-delay change.

TX normally uses a 24th-order 700-2800 Hz band-pass filter
(`sstv.cpp:2754`).

## IIR and Tone Resonators

`CIIR` implements cascaded Butterworth or Chebyshev low-pass sections. Its
designer prewarps the cutoff, calculates analog prototype poles, applies a
bilinear transform, and emits second-order sections (`fir.cpp:950`). Values
smaller than `1e-37` are cleared to avoid denormal slowdowns.

`CIIRTANK` is a separate two-pole resonator:

```text
y[n] = a0*x[n] + b1*y[n-1] + b2*y[n-2]
```

`CSSTVDEM` creates resonators at 1080, 1200, 1320, 1900, and 2100 Hz
(`sstv.cpp:1446`). Each output is full-wave rectified and smoothed by a
second-order 50 Hz low-pass filter. These envelopes drive VIS, line sync, FSK,
narrow-mode, and repeater detection.

## LMS and Notch Filters

`CLMS` provides two related adaptive filters.

`Do()` predicts the current sample from recent input and returns the prediction,
not the error. It therefore acts as an adaptive line enhancer that emphasizes
correlated narrowband content. Coefficients use a leaky LMS update, and the
output is normalized by the coefficient L1 norm (`fir.cpp:115`).

`DoN()` predicts from a delayed input and returns the prediction error. It acts
as an adaptive line canceller or notch (`fir.cpp:162`). Default sizes at 11025
Hz are approximately 48 taps and a 12-sample prediction delay.

`CNotch` creates a manually positioned FIR band-elimination filter. Its order is
approximately 96 at 11025 Hz, scaled with sample rate and capped at 256. The
notch is normally +/-15 Hz inside the SSTV image band and +/-30 Hz outside it.

The real-time order is manual notch first, followed by the selected LMS mode,
then `CSSTVDEM`.

## Level Tracking and AGC

`CLVL` records current magnitude, interval peak, and sample count. `Fix()` rolls
statistics at nominal 100 ms intervals. In fast mode, used by `CSSTVDEM`, gain
is approximately:

```text
gain = 16384 / max(interval_peak, 32)
```

This gain normalizes the resonator and detection path. The main FM
discriminators receive the unscaled BPF output; PLL has a separate internal AGC.

Level accumulation occurs in the sound thread, but the UI invokes `Fix()` while
drawing the level meter (`Main.cpp:5714`). DSP state is therefore mutated from
both threads in the original implementation.

## FM Discriminators

`CSSTVDEM::m_Type` selects one of three frequency discriminators.

### PLL

`CPLL` combines a sine VCO, multiplier phase detector, loop low-pass filter,
output low-pass filter, and cycle-based input AGC (`sstv.cpp:240`). Ordinary
operation is centered at 1900 Hz over the 1500-2300 Hz image range. Narrow mode
uses a 2172 Hz center and 2044-2300 Hz range.

The previous phase error is filtered to obtain VCO control, the input is
multiplied by the VCO output, and filtered control becomes the frequency result.

### Zero-Crossing Counter

`CFQC` measures intervals between both positive and negative zero crossings
(`sstv.cpp:346`). Crossing position is linearly interpolated between adjacent
samples, and frequency is calculated from the half-cycle duration:

```text
frequency = sample_rate * 0.5 / half_cycle_samples
```

The result is normalized around the current mode center and smoothed with an
IIR or moving average. Out-of-range measurements are clamped rather than
discarded.

### Hilbert Discriminator

`CHILL` forms an analytic signal from a Hilbert FIR output and its center-delayed
real input (`sstv.cpp:3005`). It calculates `atan2`, unwraps the phase delta,
subtracts the expected center-frequency advance, scales the result, and applies
a third-order 1800 Hz low-pass filter.

Phase differentiation spans one, two, or four samples depending on sample-rate
class. This preserves a useful phase increment at higher rates. Hilbert is the
default discriminator constructed by MMSSTV.

## Mode, Sync, and FSK Detection

The detector bank runs continuously on AGC-normalized audio. The embedded VIS
state machine compares 1080 and 1320 Hz envelopes every 30 ms, checks the
1200/1900 Hz framing conditions, and maps the resulting byte to a mode
(`sstv.cpp:1946`). MMSSTV extended VIS decodes a second byte after marker
`0x23`.

`CSYNCINT` stores eight measured sync intervals and compares them against every
mode's expected period (`sstv.cpp:1289`). It tests one-, two-, and three-line
multiples so reception can begin despite missed sync pulses or a missed VIS
header.

FSK compares the 1900 Hz mark and 2100 Hz space envelopes. It uses a 100 ms
guard and 22 ms six-bit symbols, transmitted least-significant bit first. It
decodes callsign records and the N-VIS identifiers used by narrow modes
(`sstv.cpp:2378`). AVT uses a separate PLL-based acquisition and digital sync
sequence.

Exact identifiers and per-mode timing are listed in
[sstv/modes.md](../sstv/modes.md).

## Raster Synchronization and Live Correction

Raster synchronization is not implemented by `CSSTVDEM`. The demodulator
publishes both frequency values and a parallel sync-envelope stream, while the
main form establishes and maintains raster phase.

`TMmsstv::SyncSSTV()` folds the first three or four completed demodulator pages
at the mode's nominal floating-point line period and sums their sync envelopes
(`Main.cpp:3343`). The strongest accumulated position is adjusted by the
mode-specific `m_OFP` offset to establish `m_rBase`. Scottie modes wrap a
negative result by one line, and the Hilbert discriminator requires an
additional FIR-delay correction. Accumulating several lines emphasizes a sync
pulse that recurs at a stable phase instead of accepting the first isolated
1200 Hz peak.

During raster decoding, `DrawSSTV()` records each line's sync-envelope maximum,
minimum, and peak position. `AutoStopJob()` keeps a 16-line position history and
uses both positional agreement and peak-to-minimum strength (`Main.cpp:3476`).
It serves two related purposes:

- AutoSync changes the demodulator time base only after sync positions agree
  across multiple lines and the envelope contrast is sufficiently large.
- AutoStop counts persistently weak or inconsistent lines and can terminate a
  reception instead of continuing to decode noise.

Live phase correction is communicated through `CSSTVDEM::m_Skip`. A positive
value discards incoming demodulated samples; a negative value repeats the
current demodulated value while advancing the output ring (`sstv.cpp:2271`).
After a correction, AutoSync suppresses further corrections for several lines.
The same skip mechanism compensates group-delay changes when receive filters,
the manual notch, or LMS processing are changed.

MMSSTV does not normally downsample the live receive stream. Audio capture,
front-end DSP, and the demodulated frequency/sync page buffers remain one sample
in and one sample out. At higher rates the Hilbert discriminator compares phase
over two or four samples but still emits one result per input sample. FFT display
collection is decimated separately and does not feed SSTV decoding. Raster
conversion is the many-to-one step: MMSSTV selects the first demodulated sample
entering each output pixel bin, with an optional look-ahead maximum, rather than
averaging the bin.

## Automatic Frequency Control

AFC measures frequency-discriminator output during a mode-specific interior
portion of detected horizontal sync pulses (`sstv.cpp:2339`). With the
zero-crossing and Hilbert discriminators, AFC measures the selected
discriminator directly. With PLL image demodulation, AFC deliberately uses the
parallel zero-crossing discriminator instead of the PLL control output
(`sstv.cpp:2255`). AVT bypasses this AFC path.

Only values inside the configured sync-frequency range advance the AFC sample
counter. The accepted interval is averaged, further smoothed across sync
pulses, and protected by an initial guard and an update-inhibit interval. AFC
also requires a minimum measured signal level. It computes:

```text
correction = expected_sync_value - measured_sync_value
```

The correction is added to subsequent demodulated image samples. The equivalent
frequency offset also retunes the 1080, 1200, 1320, 1900, and 2100 Hz resonators.
Thus AFC corrects both raster color values and later tone detection.

## Clock and Slant Correction

MMSSTV treats carrier-frequency error and sample-clock error separately. AFC
corrects the former. The latter appears as a gradual drift of horizontal sync
position and is represented by changing the receive mode's logical
`SSTVSET.m_SampFreq`, not by reopening the audio device at a nonstandard rate.

When real-time slant adjustment is enabled, `AutoStopJob()` first rejects
unstable sync histories, estimates a reference position from the latest five
lines by least squares, and measures its drift over subsequent lines
(`Main.cpp:3459`, `Main.cpp:3560`). The drift is converted to an effective sample
rate and smoothed over the most recent 16 estimates, averaging however many have
been collected so far. Correction thresholds become progressively
smaller as more lines are received, so early acquisition accepts only large
errors while later updates can refine the rate. Changing the rate requests a
redraw from staged demodulator data when that data is available.

`CorrectSlant()` provides a more precise staged-data pass (`Main.cpp:4838`). It:

1. Folds up to the first 32 lines of sync envelopes to find a reference phase.
2. Finds each line's strongest sync position and unwraps positions crossing the
   line boundary.
3. Rejects lines with insufficient envelope contrast or positions too far from
   the current reference.
4. Fits sync position against line number by least squares, requiring at least
   six accepted lines.
5. Converts the fitted slope to a logical sample rate and repeats the analysis
   up to five times with a narrower position window.

If the fitted rate changes, `RedrawSampFreq()` recomputes mode timing,
re-establishes raster phase, and redraws the stored frequency and sync streams
(`Main.cpp:5155`). `RedrawAdjustSync()` is a separate staged-data operation that
can shift individual lines whose sync peak differs by more than a
mode-dependent pixel-width threshold (`Main.cpp:5215`). This handles local
dropouts or abrupt timing discontinuities that a single whole-image slant fit
cannot remove.

## VCO and Modulation

`CVCO` uses a sine table with a length of twice the sample rate
(`sstv.cpp:71`). Per sample it advances phase by the free-running frequency plus
the scaled control input. The table is read at an integer index without
interpolation. The same VCO class serves the receive PLL and TX modulator.

`CSSTVMOD` owns a frequency-command ring sized in seconds and clamped to 5-14
seconds (`sstv.cpp:2794`). `Write(frequency, milliseconds)` advances a cumulative
floating endpoint and enqueues samples until the integer write position reaches
that endpoint. This avoids accumulating duration error across many pixels.

For ordinary TX, frequency is normalized relative to a 1100 Hz free frequency
and 1200 Hz control span, converted to sine PCM, scaled to a default peak of
24578, and filtered. AVT commands can carry channel tags in their high bits to
select different R, G, and B output gains.

## FFT

`CFFT` implements an in-place real transform with precomputed trigonometric
tables, bit reversal, complex FFT stages, and real-spectrum postprocessing. A
Hann window is applied before the transform (`Fft.cpp:46`). Spectrum values can
use logarithmic or linear display scaling and optional temporal averaging.

At high input rates the collector takes every second or fourth sample. One
alternate display mode bypasses the FFT and feeds samples to an unrestricted
`CFQC`, producing a zero-crossing frequency histogram.

The sound thread fills one of three 2048-sample pages. The VCL thread calculates
and draws completed pages, either by timer polling or a posted `CM_FFT` message.
The page indices are shared without atomics.

## Buffer and Thread Boundaries

`CWave` protects WinMM callback FIFOs with critical sections and Windows events.
Above that layer, the principal DSP queues are implicit single-producer,
single-consumer rings:

| Queue | Producer | Consumer |
| --- | --- | --- |
| Demodulated frequency/sync pages | Sound thread | VCL thread |
| TX frequency commands | VCL thread | Sound thread |
| FFT pages | Sound thread | VCL thread |

`CSSTVDEM` allocates 24 parallel pages for frequency values and sync envelopes.
The VCL thread can copy completed lines to a full-image memory buffer or
`Sound.tmp` for later resynchronization and slant correction.

None of the higher-level rings use atomics or memory barriers. They rely on one
writer, one reader, and the behavior of the original x86 Windows toolchain.

## Implementation Coupling

The DSP files include VCL and application headers. They also use `VirtualLock`,
`HWND`, `PostMessage`, global `sys` settings, and global sample-rate variables.
Construction order matters because several DSP objects derive table sizes and
coefficients from globals in their constructors.

The UI owns protocol encoding, image decoding, FFT rendering, and some updates
to level and AFC state. Consequently the numerical classes in `fir.cpp`,
`sstv.cpp`, and `Fft.cpp` describe only part of MMSSTV's effective DSP pipeline.
